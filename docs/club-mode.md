# 雙人賽俱樂部模式 MVP

## 裁判操作

1. 建立雙人賽，確認搭檔、賽程編排、牌號與身價。
2. 裁判後台 →「俱樂部收分」→ 啟用俱樂部模式。
3. 填入手機可連線的網站網址，逐對產生 QR／專屬連結並發給對應搭檔。同一對可用多台手機。
4. 「圈次與發布設定」指定當前圈數，狀態設為進行中。
5. 搭檔輸入當桌成績，各自確認本圈。
6. 「俱樂部收分」檢查收分與確認進度，按「結算並發布本圈」。系統會進入圈間休息，再由裁判指定下一圈。

連結只在產生時顯示。重新簽發使舊連結立即失效，但不解除該搭檔已確認的本圈狀態。
本機 `127.0.0.1` 只能在本機使用；其他手機需使用部署網址或可連線的區域網路網址。

## 搭檔收分

開啟專屬連結 → 選當圈牌號 → 填合約、莊家、賭倍、實得墩數及選填首引 → 檢查 NS 原始分 → 儲存。
儲存即重新計分；最後成功送達的成績覆蓋之前的輸入。若圈次、權限或鎖定已改變，提交會被拒絕。
每 10 秒讀取最新成績；讀取不覆蓋正在編輯的表單。換圈會清除舊圈草稿。

確認前須收齊本桌本圈所有牌。確認鎖定的是該搭檔本圈的提交權，涵蓋所有共用此連結的裝置。
另一對仍可更正；已確認的一方仍會看到最新成績。輪空不需確認。
取消的牌只能由裁判／賽務在後台處理，搭檔不能恢復。

## 結算、發布與權限

正常結算要求本圈每桌收齊結果、每對完成確認。裁判可填原因後強制結算：未確認者記為強制確認，缺分牌記為取消，均保留操作紀錄。強制結算後直接進入下一圈「進行中」；最後一圈結算後保持圈間休息。
結算後選手不能再修改；裁判／賽務可用現有後台更正。
本圈已收成績包含已送出但尚未確認的成績，只公開收件數，不提前公開分數。
觀眾 API 僅回傳已結算圈的成績並據此計算排名；牌型還須符合既有公開設定，且該副所有安排的圈次都已結算。
未形成比較的單一有效結果不產生比較分數，也不阻擋結束賽事。
停用俱樂部模式會恢復一般模式的成績公開方式，介面會提示。

專屬連結的憑證放在 URL fragment，以 Authorization header 傳給收分 API；資料庫只保存 SHA-256 雜湊。
收分 API 只回傳自己當圈桌次、結果及牌號／發牌方／身價，不回傳牌型或其他桌成績。
每次寫入會在版本檢查及儲存鎖內再次檢查憑證、當圈、桌次與確認狀態。

MVP 不包含桌上平板模式、離線送分、逐桌發布例外、解除搭檔確認或操作紀錄 rollback。
需要修改已確認結果時，請裁判使用後台更正。

## 驗證

- `npm test`：俱樂部權限、確認、強制／正常結算、發布過濾、輪空與憑證重新簽發。
- `node node_modules/tsx/dist/cli.mjs scripts/club-smoke.ts`：只對 local 模式建立暫存賽事，測試 HTTP 權限、並行提交及結算，最後刪除暫存賽事。
