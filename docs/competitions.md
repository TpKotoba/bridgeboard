# 賽事與賽段

- `/` 是賽事入口，只顯示賽事卡片與搜尋。
- `/?competition=<id>` 是賽事主頁，顯示共用名稱、前綴、日期、地點與賽段選擇。
- `/?event=<id>&view=...` 保留既有成績深連結，進入選定賽段的 Dashboard 與表格。
- 不設賽段時，主頁提供「進入賽事」。設立賽段後，各賽段可有不同名單、隊制／雙人賽、計分法、賽程、收分與牌型。
- 裁判從入口建立賽事時可選「設立賽段」並命名第一賽段；也可在既有賽事主頁按「設立賽段」，保留原有成績並命名第一賽段，再建立新賽段。
- 共用資訊只在賽事主頁編輯。各賽段後台可改賽段名稱；共用日期亦用於各圈時間預設日期。
- 賽段內沒有比賽切換器，使用「返回賽事主頁」選擇賽段，或「瀏覽其他賽事」回入口。

## 儲存與相容性

為保留既有 ID、QR 連結與操作紀錄，原有 `BridgeEvent` 根紀錄繼續持有第一份成績，並作為賽事共用資訊的來源；`hasStages` 與 `stageName` 描述分段狀態。其他賽段以 `parentEventId` 指向根紀錄。
根紀錄沒有 `parentEventId`；不允許建立巢狀賽段。讀取賽段時，`getEvent` 從根紀錄取得當前日期與地點，附上 `competition` 資訊。衍生的 `competition` 不寫回資料庫。
新增賽段同時更新根紀錄與新增獨立成績文件：local 使用既有儲存鎖與整檔原子替換；Neon 使用同一 SQL CTE 與根紀錄版本檢查。不需新增資料表或預先改寫既有資料。
有其他賽段的根紀錄不能刪除，避免孤立賽段；應先刪除其他賽段，再刪除根賽事。各賽段成績不跨段累積。

## 驗證

- `npm test`：舊資料相容、分段後保留原有成績、不同格式與名單、共用資訊繼承、版本衝突、禁止巢狀賽段。
- `node node_modules/tsx/dist/cli.mjs scripts/competition-smoke.ts`：local API 整合測試，建立暫存賽事與賽段，結束時清除。
